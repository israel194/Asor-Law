# Remote signing API (חתימה מרחוק)

Contract between the office app ("עשור דסק", runs on the office PC) and the public half
on the firm's website: the Cloudflare Worker `asor-digital-api` (`worker/src/sign.js`) and
the client page `/sign/` (`sign/index.html`, `sign/sign.js`).

- The office app creates a request, sends the returned link to the client, polls for the
  result, composes the signed PDF locally and then deletes the request.
- The Worker never edits PDFs. It stores the document encrypted, shows it to the client
  after an identity check, collects a signature image and an audit record.
- Base URL: `https://asor-digital-api.israel-486.workers.dev` (local: `http://localhost:8787`).
- All timestamps are ISO 8601 UTC (`2026-11-11T09:30:00.000Z`).
- Every `/api/sign/*` response carries `Cache-Control: no-store` and
  `X-Robots-Tag: noindex, nofollow, noarchive`.
- Errors are JSON: `{ "error": "<code>", ... }`.

## The link and the key

`POST /api/sign/requests` returns

```
https://asor-law.com/sign/#<id>.<key>
```

- `<id>`: 128 random bits, base64url, 22 characters. Identifies the request.
- `<key>`: 256 random bits, base64url, 43 characters. Generated by the Worker, returned
  once, never stored. It lives in the URL fragment, so browsers do not send it in the
  request line, in `Referer`, or to any log. The page posts it in the JSON body of each call.
- From the key the Worker derives (HKDF-SHA-256) an AES-256-GCM key and an HMAC key. The
  PDF, title, signer name, message, signed name, signature image, IP address, user agent
  and decline reason are stored only as AES-GCM ciphertext (random 96-bit IV per blob,
  the request id and blob purpose as associated data).
- **The office app must keep the returned `url` (or the key) until it has fetched the
  result.** Without it nothing can be decrypted, by anyone.

## Office endpoints

Header on every call: `Authorization: Bearer <SIGN_API_KEY>`.

| Situation | Response |
|---|---|
| Worker secret `SIGN_API_KEY` missing or shorter than 32 characters | `503 signing_not_configured` |
| Header missing or wrong (constant-time comparison) | `401 unauthorized` |
| More than 120 office calls per minute from one IP | `429` |

No CORS headers are ever sent on `/api/sign/requests*` (server to server only).

### 1. `POST /api/sign/requests`

`Content-Type: application/json`, body up to 14.5 MB.

```json
{
  "title": "ייפוי כוח",
  "signer_name": "שם מלא של החותם",
  "verify": { "kind": "id_last4", "value": "1234" },
  "expires_hours": 168,
  "fields": [ { "page": 2, "x": 0.55, "y": 0.80, "w": 0.30, "h": 0.08 } ],
  "message": "הערה ללקוח (לא חובה)",
  "pdf_b64": "<base64 of the PDF>",
  "page_count": 2
}
```

| Field | Rules |
|---|---|
| `title` | string, 1 to 200 characters |
| `signer_name` | string, 1 to 120 characters |
| `verify.kind` | `"id_last4"` (value: exactly 4 digits) or `"code"` (value: 4 to 64 characters after removing spaces and hyphens; compared case-insensitively) |
| `expires_hours` | integer 1 to 720, default 168 |
| `fields` | array, 0 to 20 items. `page` is 1-based; `x`, `y`, `w`, `h` are fractions 0..1 of the page, origin top-left; the box must stay inside the page. Empty array or omitted: the signature goes on an appended page |
| `message` | optional string, up to 1000 characters |
| `pdf_b64` | standard base64, decoded size up to 10 MB, must start with `%PDF-` |
| `page_count` | optional integer (addition to the contract, see below) |

`201`:

```json
{ "id": "…22 chars…", "url": "https://asor-law.com/sign/#<id>.<key>", "expires_at": "2026-11-18T09:30:00.000Z" }
```

Errors: `400 invalid_title | invalid_signer_name | invalid_message | invalid_verify |
invalid_expires_hours | invalid_fields | invalid_page_count | invalid_pdf_b64 | not_a_pdf |
invalid_json`, `413 pdf_too_large | payload_too_large`, `415 unsupported_media_type`.

Only a salted HMAC of the verification value is stored (HMAC key derived from the request
key, so the 4 digits cannot be brute-forced from a storage dump), with an attempt counter.

### 2. `GET /api/sign/requests/<id>`

```json
{
  "status": "pending | viewed | signed | declined | expired",
  "created_at": "…", "viewed_at": null, "signed_at": null, "expires_at": "…",
  "audit": {
    "ip": null, "user_agent": null,
    "verified": false, "consent_text": null, "attempts": 0,
    "verify_kind": "id_last4", "verified_at": null, "document_served_at": null
  },
  "locked": false, "locked_at": null,
  "declined_at": null, "decline_reason": null
}
```

- `audit.attempts` counts wrong verification values. After 5 the request is locked:
  `locked: true`, `locked_at` set, `status` stays `pending`/`viewed` (until it expires), and
  the stored PDF is deleted. A locked request cannot be unlocked; create a new one.
- `audit.ip`, `audit.user_agent` and `decline_reason` are encrypted at rest. They are
  returned only when the call also carries `X-Sign-Key: <key>`; otherwise they are `null`.
  A wrong key gives `403 wrong_key`.
- `404 not_found` when the request does not exist (deleted or purged).

### 3. `GET /api/sign/requests/<id>/result`

Requires `X-Sign-Key: <key>`. Only when `status` is `signed`.

```json
{
  "signature_png_b64": "<PNG, transparent background, trimmed to the ink>",
  "signed_name": "…",
  "signed_at": "…",
  "audit": { "ip": "…", "user_agent": "…", "verified": true, "consent_text": "…", "attempts": 0,
             "verify_kind": "id_last4", "verified_at": "…", "document_served_at": "…" },
  "pdf_sha256": "<hex sha256 of the original PDF exactly as received>",
  "fields": [ { "page": 2, "x": 0.55, "y": 0.80, "w": 0.30, "h": 0.08 } ]
}
```

Errors: `400 missing_sign_key`, `403 wrong_key`, `404 not_found`,
`409 not_signed` (with the current `status`).

The office app should check `pdf_sha256` against its own copy before composing the signed PDF.

### 4. `DELETE /api/sign/requests/<id>`

Deletes every stored byte of the request (record, PDF, signature). `200 { "deleted": true }`,
or `404 not_found` if nothing was there.

## Retention

| Event | What is deleted | When |
|---|---|---|
| Signed | the PDF | immediately |
| Declined, or locked after 5 wrong attempts | the PDF | immediately |
| Expiry without signature | the PDF | at `expires_at` |
| Expiry without signature | the record | `expires_at` + 7 days |
| Signed or declined | the record and the signature | 30 days later |
| `DELETE` | everything | immediately |

Implemented with Cloudflare KV expirations on the existing `ORDERS_KV` namespace (keys
`sign:<id>`, `sign:<id>:pdf`, `sign:<id>:sig`). No scheduled handler is needed.

## Client endpoints (used by `/sign/`)

All are `POST` with `Content-Type: application/json`; the body always contains `id` and
`key`. CORS is limited to the origins in `CORS_ORIGINS`. Unknown id and wrong key give the
same `404 not_found`.

| Endpoint | Body (besides `id`, `key`) | Success |
|---|---|---|
| `/api/sign/open` | (none) | `{ status, firm_name, title, signer_first_name, message, page_count, verify_kind, attempts_left, expires_at, signed_at, declined_at, consent_text }`; marks the request `viewed`. `status` here may also be `locked` |
| `/api/sign/verify` | `value` | `{ session, session_expires_at, page_count, fields, consent_text }`. Wrong value: `401 wrong_value` with `attempts_left`; the fifth: `423 locked` |
| `/api/sign/document` | `session` | the decrypted PDF bytes, `Content-Type: application/pdf` |
| `/api/sign/submit` | `session`, `signature_png_b64`, `signed_name`, `consent: true` | `{ status: "signed", signed_at }` |
| `/api/sign/decline` | `session`, `reason` (optional, up to 500 characters) | `{ status: "declined", declined_at }` |

- The session token is 256 random bits, valid 30 minutes, stored as a SHA-256 hash, bound
  to one request, and cancelled at signing or declining.
- `submit` requires: `consent === true`; `signed_name` 2 to 120 characters; a structurally
  valid PNG of at most 300 KB (signature bytes, IHDR, chunk walk, IEND); the document must
  have been served in this request (`409 document_not_viewed` otherwise).
- Replay: once signed, `submit` answers `409 already_signed`, and `document`, `verify`,
  `decline` answer `409` with the status.
- Other errors: `401 session_invalid`, `409 not_active` (with `status`), `413`, `415`, `429`.
- Rate limits (fixed one-minute windows in KV): per IP 40 calls (`open`, `document`,
  `submit`, `decline` together) and 10 `verify` calls; per request id 30 calls and 10
  `verify` calls. The limit that actually protects the identity check is the 5-attempt lock.
- The consent text recorded in the audit is fixed in the Worker (`CONSENT_TEXT` in
  `worker/src/sign.js`) and is the same string the page shows next to the checkbox.

## Differences from the original brief

1. `GET /api/sign/requests/<id>`: `audit.ip` and `audit.user_agent` are returned only with
   `X-Sign-Key`. The brief asks both for these fields and for all personal data to be
   encrypted with a key the Worker does not keep; the two cannot hold together without the
   key. The office app always has the key, so it should send the header on every poll.
2. Status has an extra `locked` / `locked_at` (the status enum has no "locked" value), plus
   `declined_at`, `decline_reason`, and three extra audit fields.
3. `POST /api/sign/requests` accepts an optional `page_count`. The Worker does not parse
   PDFs; without it the page count is a best-effort guess (may be `null`) and `fields[].page`
   is validated against it only when known. The page itself takes the real count from the PDF.
4. `/api/sign/document` is `POST` only (not GET), so the key and session never appear in a URL.
5. `result` also returns `fields`, for convenience.
6. `SIGN_API_KEY` must be at least 32 characters, otherwise the office endpoints stay at 503.

## Known limits

- Cloudflare KV is eventually consistent and has no atomic counters. Two simultaneous
  wrong attempts may be counted as one, and two simultaneous submissions are resolved
  last-write-wins (still a single stored signature). An attacker needs the full link to
  exploit this at all. A Durable Object would make it strict; it was not added because the
  stack has none today.
- The Worker reads the whole create body into memory (up to about 14.5 MB of JSON) and
  encrypts it; this needs the Workers Paid CPU limits the account already uses.

## Setup (run by the account owner, once)

```bash
cd worker
npx wrangler secret put SIGN_API_KEY     # paste a random value of 32+ characters when prompted
npx wrangler deploy
```

Generate the value locally, for example with
`node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`, and store
the same value in the office app's configuration. Do not put it in a command line, in
`wrangler.toml` or in the repository. No new KV, R2 or D1 binding is required.

## Local run and tests

```bash
cd worker
npm test                                  # in-memory: real routes, fake KV, fake clock

SIGN_TEST_BASE=http://127.0.0.1:8787 SIGN_TEST_KEY=<the same test value> npm test
```

Serve the site root on `http://localhost:8080` (the origin already allowed in
`CORS_ORIGINS`) and open the `url` returned by `POST /api/sign/requests`.
